# Structured Extraction: baseline на локальном корпусе

Дата прогона: 12 ноября 2026. Это baseline до исправления найденных дефектов.

## Итог

В локальном Document Parser обработаны все 22 уникальных первичных документа. Все 22 результата прошли через адаптер и Rules Only. Это подтверждает выполнение конвейера, но не означает высокую точность: система уверенно обрабатывает только часть актов, не классифицирует КФЗ и счёт, а таблица КФЗ дублируется и теряет значения при структурированном извлечении.

LLM Assisted и Compare не запускались на первичных документах. В набор входят зарплатные и страховые ведомости, а разрешение отправить их во внешний сервис не подтверждено. Документы остались локальными. Отдельный реальный smoke test Polza выполнен на демонстрационном КФЗ из тестовой D1.

## Корпус и метод

В каталоге было 26 файлов: 10 PDF, 11 XLSX, 3 DOCX, 1 PNG и 1 TXT. Один PDF представлен двумя побайтово одинаковыми копиями. Три файла — описание набора и эталонный XLSX; после их исключения и удаления дубликата остаются 22 уникальных первичных документа: один КФЗ, пять зарплатных ведомостей, пять ведомостей страховых взносов, шесть актов, один счёт-акт, две УПД, служебная записка и справка.

Для OCR, Docling и анализа Office использовались исходники из локального репозитория Document Parser, без заранее подготовленных parser JSON. Фактически были обработаны 24 уникальных файла поддерживаемых форматов: 22 первичных документа и два справочных файла. TXT-описание не передавалось в Docling. Повторная копия PDF не запускалась второй раз.

| Компонент | Версия / commit |
| --- | --- |
| Document Parser | `4c2fd27ae6f7ebd0a9a9f9c052099c12b56f5e84` |
| Docling | 2.72.0 |
| OCR | локальный RapidOCR 3.6.0, распознавание Cyrillic PP-OCRv5 |

OCR использовал локальную модель; опциональные Polza OCR fallback/review были отключены. Время обработки первичных документов — в среднем 2,97 секунды. Все 22 завершились без ошибки; суммарно зарегистрировано 7 предупреждений Parser, включая недоступные кешированные результаты формул XLSX. OCR-качество по всему корпусу не размечалось.

## Классификация

Схемы приложения поддерживают КФЗ, акты и счета из этого корпуса. Остальные 14 документов (ведомости, УПД, служебная записка и справка) не включены в точность классификации: для них нет соответствующих специализированных схем.

На 8 документах поддерживаемых классов:

| Класс | Поддержка | Precision | Recall | F1 |
| --- | ---: | ---: | ---: | ---: |
| КФЗ | 1 | 0% | 0% | 0% |
| Акт | 6 | 100% | 66,7% | 80% |
| Счёт | 1 | 0% | 0% | 0% |
| Micro / accuracy | 8 | 50% | 50% | 50% |
| Macro F1 |  |  |  | 26,7% |
| Weighted F1 |  |  |  | 60% |

Четыре из восьми документов получили `unknown` и статус `review`: КФЗ, счёт и два акта. Всего из 22 документов система классифицировала как `act` четыре; остальные 18 получили `unknown`. Вне поддерживаемых схем остались 14 документов.

Ожидаемый тип для этой метрики присвоен по исходному имени/заголовку файла, независимо от результата извлечения. Адаптер передаёт имя файла классификатору, поэтому оценка не является слепой: входная metadata уже содержит сильный признак класса. Метрики ниже показывают результат на реальном входе, но не заменяют отдельную разметку специалистом, который не видит filename.

## Извлечение полей и таблиц

Полные Field Precision/Recall/F1 и Hallucination Rate не публикуются: независимая полевая разметка всего корпуса не завершена. Полный эталонный XLSX хранится локально в исходном корпусе, исключённом из Git. Для КФЗ независимо размечена целевая строка «3 этап, 2026 г.»: 15 числовых ячеек, проверенных по изображению исходной страницы и сопоставленных с эталонной книгой там, где данные пересекаются.

По этой строке: точных значений извлечено **0 из 15**, recall по ячейкам — **0%**, Exact Match Accuracy — **0%**. Precision и F1 по ячейкам не определяются, поскольку система не выдала ни одного значения-кандидата.

Обнаружены два связанных дефекта таблицы КФЗ:

1. В исходном Parser JSON одна таблица содержит 9 строк и 17 столбцов. Одна и та же таблица есть в `parts` и `visual_layout`; адаптер объединил обе копии и передал 18 строк (306 ячеек). Это подтверждённое удвоение.
2. Все 18 строк получили `row_status: extracted`, хотя все значения полей строк имеют `status: missing`. Ни одна строка не содержит извлечённых значений. Для целевой строки row Precision/Recall/F1 равны 0/0/0; заполненный статус строки является ложным.

Точность выбора столбцов и многоуровневых заголовков на этом результате не подтверждена: значений, сопоставленных полям, нет. Пять документов потребовали OCR; реальная посимвольная точность для них отдельно не измерялась.

## Provenance и grounding

В Rules Only найдено 43 выданных значения: 15 полей и 28 значений таблиц. Для всех 43 проверено, что ID источника разрешается в элемент адаптера, источник не помечен недоступным, локатор и текст присутствуют, а исходное значение содержится в `source_text`. Это **43/43 проверок лексического grounding**, а не доказательство семантической точности. Provenance Recall и доля галлюцинаций не измерялись из-за незавершённой независимой разметки.

Неполная таблица КФЗ не содержит принятых значений и потому не даёт оснований считать её корректно grounded. 43/43 относится только к значениям, которые были выданы другими результатами Rules Only.

## Polza AI и режимы

- Первичные документы: 0 вызовов Polza; `llm_assisted` и корпусный `compare` не запускались из-за конфиденциальности.
- Изолированный synthetic demo smoke: 1 GET `/models`, модель найдена; один Compare вызов `deepseek/deepseek-v4-flash` прошёл локальную валидацию и был сохранён в тестовую D1.
- Повторное чтение сохранённого demo результата из D1 прошло. Это подтверждает интеграцию и не является метрикой по реальному корпусу.

## Проблемы и ограничения

- КФЗ определяется как `unknown`, поэтому профильные поля не извлекаются.
- Счёт также определяется как `unknown`.
- Адаптер дублирует таблицу КФЗ из `parts` и `visual_layout`.
- Для КФЗ `row_status` сообщает `extracted` при полностью пустых значениях.
- 14 документов относятся к типам без профильной схемы приложения.
- Нет независимой полной разметки полей и строк для оставшихся 21 документов; общие field/table метрики, Hallucination Rate и OCR accuracy не заявляются.
- LLM Assisted и Compare по корпусу не измерены; сравнение Rules Only и LLM Assisted для этих документов отсутствует.
- Формулы XLSX повторно не вычислялись; пять файлов содержат предупреждения о недоступных кешированных значениях.

Вывод: запуск Parser и переход через Rules Only подтверждены, но стабильный MVP на этом корпусе пока не подтверждён. Перед использованием результата КФЗ нужна ручная проверка; сначала необходимо устранить дублирование таблиц и неверный `row_status`, затем расширить классификацию и независимую разметку.

Подробные обезличенные результаты находятся в [`benchmarks/results/summary.json`](benchmarks/results/summary.json) и [`benchmarks/results/per-document.json`](benchmarks/results/per-document.json). Локальные документы, полные parser JSON и эталонная разметка в Git не добавлены.
