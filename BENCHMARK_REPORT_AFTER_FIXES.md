## Объём и конфиденциальность

Из оригинальной папки корпуса заново обработаны локальным Document Parser 22 уникальных первичных документа. Исключены три файла с описанием и эталонной разметкой; побайтовый дубликат обработан один раз. Для пяти документов Parser включил локальный OCR. Использованы исходные файлы, а не сохранённые Parser JSON. После прогона каждый результат прошёл адаптер и Rules Only; ошибок Structured Extraction не было.

Зарплатные и страховые документы не отправлялись в Polza. Для всего корпуса не подтверждалось разрешение на внешнюю обработку, поэтому LLM Assisted и Compare на нём не запускались. Полные документы, Parser JSON и числовая эталонная разметка остались в локальном исключённом каталоге. В Git публикуются только обезличенные количества и статусы.

## Исправления таблицы КФЗ

Parser представил таблицу через `logical_tables`: 9 физических строк, где пять строк относятся к многоуровневому заголовку и строке нумерации колонок, а четыре — к данным. Каждая логическая строка также содержит ссылку на физический фрагмент; сам фрагмент повторяет ту же сетку. Адаптер больше не считает эти копии дополнительными строками и сопоставляет их по странице и физическому номеру строки, не удаляя одинаковые значения в разных позициях документа.

Адаптер восстановил 17 колонок и иерархические заголовки из строк таблицы, сохранив ссылки на источники, страницы и bbox. Из четырёх строк данных целевая строка содержит все 15 числовых значений из независимой разметки. Все 15 совпали после нормализации чисел. Результат намеренно требует проверки из-за одной другой пустой ячейки; пустые и частичные строки не помечаются как полностью извлечённые.

## Классификация и схемы

Добавлены отдельные схемы и метки для счёта-акта, УПД, ведомости заработной платы, ведомости страховых взносов, служебной записки и справки. Существующие схемы договора, акта, счёта, КФЗ, дополнительного соглашения и реестра сохранены. Классификатор анализирует текст и структуру Parser, не использует filename/title как признак. Unit-регрессии проверяют КФЗ, счёт и новые типы при переименованном файле.

`not_scored` сохраняется для полной классификационной точности: категория в исходном индексе и имени файла ещё не является независимой слепой разметкой. Все 22 текущих вывода совпали с исследовательскими метками, но это наблюдение не объявляется accuracy.

## Реальная Polza AI проверка

- Провайдер: Polza AI (`GET /models` успешно).
- Модель ответа и сохранённого запуска: `deepseek/deepseek-v4-flash`.
- Документ: только синтетический demo `kfz-2026-q1`.
- Успешный настоящий completion: 1, режим Compare; Rules и LLM результаты сопоставлены.
- Ответ прошёл локальную структурную и provenance-валидацию, был сохранён в локальную D1 и прочитан обратно.
- Latency успешного вызова: около 17,5 секунды; usage от API: 12 753 токена всего.
- Отдельная попытка запустить API mode `llm_assisted` получила HTTP 429 от локальной защиты дневной квоты до отправки inference-запроса. Лимит не обходился и эта попытка не считается успешным вызовом.
- Ни один документ корпуса не передавался внешнему провайдеру.

Секрет хранится в игнорируемом `.dev.vars`; значение ключа не включено в запросы Git, логи, JSON benchmark или этот отчёт.

## Ограничения оценки

- Полные field-level precision, recall, F1, exact match и общие метрики строк — `not_scored`: для 21 документа нет независимой подробной разметки.
- Метрика КФЗ относится к одной вручную проверенной строке, а не ко всем таблицам корпуса.
- Внешний LLM benchmark на рабочих документах не проводился из-за отсутствия разрешения на обработку.
- Отдельный API путь `llm_assisted` не завершил inference в повторной проверке из-за локального лимита; Compare успешно использовал реальный LLM pipeline с тем же LLM-assisted extraction path.
- Кешированные результаты формул XLSX не пересчитывались Parser; такие ячейки продолжают требовать ручной проверки.
